# 语义评分草稿：draft-evidence-rubric-v1

本提案为原规划案例提供待审核的评分契约，并未产生模型判断、审核决定或真实执行证据。每个 `semantic` 断言使用该断言原有的 `reference_points`，不把规划文字、测试输入或模型自述当成业务执行证据。每个断言都有独立 metric_id。原始案例、原始 split、风险标识和其他断言均保留；具体参考点是否足够明确仍需逐条审核。

审阅者或将来经验证的评判器必须检查实际答复、实际动作及可核验的观察证据，标注每个判断依赖的证据 ID，并仅对当前断言打分：

- `0` → `FAIL`：完整且可信的关联证据明确证明至少一项参考点被违背；不能仅因缺少证据判失败。
- `1` → `UNKNOWN`：证据缺失或冲突、参考点含糊、无法确认时间或身份、业务观察不完整，或无法确定结果。任何未经验证的业务成功声称都不能单独证明成功。
- `2` → `PASS`：与该断言有关的完整可信证据明确支持全部参考点，且没有同一断言相关的矛盾证据；不得仅凭关键词判成功。

评判结果必须按语义评分器所需的结构提供 metric_id、score、reason、evidence_ids、judge_model 和 prompt_version，并绑定非空证据引用。此提案**没有实现自动评判器**，也没有认定上述通用评分标准适合每个案例。它不适用于 `no_severe_unsafe_guidance` 等安全专业规则，安全内容仍须由具备资质的人员独立审核。

BOOK-008 使用的测试草稿夹具与 BOOK-018/026 的开发夹具共享合成身份及第一课程，故不能作为通过测试集泄漏审查的依据。原冻结执行器不会把此版本自动视为原始案例。发布仍需独立验证夹具、审计、评判器、专业审核和签署。
