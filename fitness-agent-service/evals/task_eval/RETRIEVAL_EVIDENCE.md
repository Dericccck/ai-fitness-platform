# 知识检索的请求级证据 ID

当对话的生产 `Supervisor` 使用已验证身份调用 `RagService.search` 并将返回的证据
上下文加入模型提示时，`retrieved_evidence_ids` 记录该次调用实际返回的分块 ID。
该字段不是模型生成或按期望答案推断，保持去重后的召回顺序；多意图调用时记录
本次请求中所有对应结果。空列表在普通 `/api/v1/agent/chat` 响应中省略，兼容未
使用检索的现有响应。它仅在当前请求上下文中收集，不写入 LangGraph 的状态或
checkpoint。检索范围仍由经验证的主体、机构和角色确定，数据库负责 ACL 过滤。

这些 ID **只表示检索结果**，不表示模型必然引用、理解或正确使用了材料，也不
证明被引用片段支持答案。测评仍需核对固定隔离语料、实际生产仓储查询及授权、
真实 embedding 和重排、回答中的引用，以及专业或语义审核。测试中的仓储、嵌入、
重排及回答替身只验证传递和隔离，不构成真实检索或任务通过的证据。

对于实际运行过 RAG 的 `FITNESS_KNOWLEDGE_QA`，系统提示要求使用 `[证据N]`。
生成结束后仅依据该次检索的顺序核对 N；零命中、缺标记、格式错误或数字越界时
返回明确回退，不能把检索结果或模型自行给出的其他来源称为已验证引用。一次请求
中发生多次知识检索而编号可能歧义时，返回回退且不输出编号映射。`knowledge_citation_evidence_ids`
是单次检索的有序候选映射，下标 N-1 对应 `[证据N]`，不等于该条引用已被使用。
普通及流式终态通过同一已鉴权响应返回映射；知识回答流先缓冲，再输出校验后的内容。
字段缺失时没有来源绑定承诺。无 RAG 或无身份沿用一般对话行为，不能声称来源已经
验证。编号有效只证明该编号对应一次检索所得分块，不能验证文字、其他链接或自然
语言中自称的来源，更不验证医学正确性。

## 固定合成 KNOW-001 隔离观察

`scripts/task_eval_rag_real.sh` 在本地 Docker Unix socket 上创建随机命名、单容器专用
bridge 网络，PostgreSQL 的随机端口仅绑定 `127.0.0.1`，数据库目录为 tmpfs，运行后
分别清理本次容器和网络。bridge 本身**不阻断**数据库容器出站流量；不得将其描述
为网络完全隔离。程序核验容器标签、网络成员、端口绑定和数据库目标，创建独立临时
数据库、迁移后只写固定的三条合成文档。Embedding 与重排使用现有本地模型，真实
DeepSeek 仅接收固定问题及上述经授权召回的合成文本。B 机构合成文档在 B 身份下有
独立正向控制，并核查它未出现在 A 身份的检索结果中。这不代替完整 ACL 安全测试。

运行需新建的私有报告路径、已有 0700 私有回答目录、私有凭证文件、现有耐久预算
账本及明确的当前价格确认；可用 `python -m app.evaluation.task_eval.dev_real_rag --help`
查看参数，并通过外层脚本执行。报告中只有哈希、检索 ID、引用编号及资源状态，
回答放在私有目录。输出为 `UNKNOWN`、待人工审核；前期仅观察一次，不是盲测、不等于
专业审核或任务通过。不要在共享日志中输出回答、数据库密码或模型凭证。

同一个驱动通过 `--case-id KNOW-001` 至 `--case-id KNOW-007` 支持七条固定的
开发案例；每条都有单独固定的合成语料、预期相关分块和跨机构对照，执行前核对
原始案例问题、数据集摘要及草稿状态。报告记录该次合成夹具的 SHA-256，夹具和
相关性均未经专业审核；不能将这些文本视作医疗建议或已验证的检索标准。扩展
驱动和测试本身不代表这六个新增案例已经执行：只有实际运行产生的报告才是一次
观察，报告仍须将回答语义支持与完整任务状态保留为未审核/UNKNOWN。
