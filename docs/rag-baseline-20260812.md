# RAG 真实检索基线报告

## 1. 验证范围

本次验证对应开发路线中的“真实 RAG 基线验证”，用于记录 PDF 解析专项优化前的可重复对照结果。
验证只使用健身知识库，不处理赛事、作品和活动运营遗留模块。

验证环境：

- Agent API：本地 FastAPI，`127.0.0.1:8090`
- PostgreSQL/pgvector：`fitness_agent` 数据库，宿主机端口 `5433`
- Redis：宿主机端口 `6380`
- Embedding：本地 BGE-M3，1024 维
- Reranker：本地 BGE-Reranker Base
- 检索链路：向量召回 + PostgreSQL 关键词召回 + RRF 融合 + Reranker + 父节点引用
- 验证身份：临时签名 `STUDENT` 上下文，仅用于本地测试

## 2. 真实接口结果

接口：`POST /api/v1/agent/knowledge/search`

| 查询 | HTTP | 主要召回结果 | 结论 |
| --- | ---: | --- | --- |
| 高温天气怎么运动 | 200 | 高温运动防护、居家运动处方、运动处方共识 | 主题召回正确，但第 5 名出现网站导航噪声 |
| 如何提高肌肉耐力 | 200 | 肌肉耐力指南、全民健身指南解读、运动处方共识 | 主题召回正确，但正文含字体映射异常字符 |
| 运动前需要热身吗 | 200 | 运动处方共识、居家运动处方 | 主题召回正确，但结果仍带网页 PDF 页脚模板 |

真实结果中的典型问题：

- `高温运动防护四注意_国家体育总局` 的召回结果包含“无障碍浏览、网站导航、公务员邮箱”等网页导航。
- 正文存在 `⽆`、`⾼`、`⼈` 等 PDF 字体映射异常字符，影响可读性和关键词一致性。
- 页脚包含“打印此页、关闭窗口、国家体育总局版权所有”等与健身知识无关的模板文本。
- 当前父节点继承了整页网页模板，父节点平均长度过大，补充上下文时会把噪声一起带入。

## 3. 离线评测结果

执行命令：

```bash
make agent-eval
```

结果：

- Recall@5：`1.0`
- MRR：`1.0`
- 用例数：`2`
- 禁止结果命中数：`0`
- 阈值校验：通过

说明：当前离线集规模较小，只能证明基础检索链路可用，不能覆盖网页 PDF 噪声、复杂表格和父节点质量。
PDF 解析专项完成后必须扩充真实问题集，并比较优化前后的 Recall、MRR、引用准确率和噪声率。

## 4. 权限基线结果

- 缺少 `X-Agent-Context`：HTTP `401`。
- 伪造签名上下文：HTTP `401`。
- `org-1` 和 `org-999` 的查询结果相同，这是因为当前已发布的 273 个 chunk 全部是 `GLOBAL`，并允许
  `SYSTEM_ADMIN`、`ORGANIZATION_ADMIN`、`COACH`、`STUDENT` 四种角色。

这说明服务端签名校验已经生效，但当前资料集没有组织级或私有资料，暂时不能证明跨组织数据隔离；后续
需要增加带组织范围的测试资料，验证组织、角色和用户所有者过滤。

## 5. 基线结论与后续对照

当前 RAG 的业务主题召回已经跑通，基础离线指标通过；但真实返回内容证明解析质量仍未达到企业级发布标准。
下一阶段进入复杂 PDF 解析质量专项，重点处理：

1. 网页导航、版权模板和页眉页脚过滤。
2. 目录、页码点线和图表标题识别。
3. PDF 字体映射异常字符与断词修复。
4. 父节点长度和内容质量控制。
5. 表格表头、数据行和跨页表格结构恢复。
6. 引用页码、噪声率和父子节点完整性自动评测。

原始资料保留不变。解析优化完成后使用同一批查询重新执行本报告中的接口测试，形成前后对照。
