## 0. 执行前约定

- 保留当前工作区用户改动；先记录基线，不重置仓库。若需要隔离开发，使用适当工作区并明确包含哪些现有改动。
- 文中 Python 路径以 fitness-agent-service/ 为根；Java 路径以仓库根为根。小程序和 App 仓库位置尚未提供，不能把 fitness-web 当移动客户端工程。

- 不开发自建视频抽帧、切片、转码、骨架或独立画质评分服务；必要文件元数据校验必须有界。
- 不新增绕过现有确认机制的训练计划写入。多模态结果只用于分析和问答。
- 每个工作包注明完成证据：代码差异、接口schema、迁移验证、测试结果、真实账号/真机验证记录；不把“设计上支持”登记成“已验证”。

## 工作包03：移动登录到 AgentIdentity 的桥接

**负责人：认证后端 + Agent后端 + 客户端。依赖：01。**

1. 确认现有小程序/App业务登录返回什么可信证明，认证端如何查询当前用户与机构权限；没有对应接口时在认证服务新增受保护的移动交换接口。
2. 微信登录码由业务服务器兑换并绑定内部用户；不要让Agent直接相信openid或客户端提供角色。App登录使用同一内部用户映射。
3. 新增 mobile_auth.py、移动认证路由与中间件，使用不透明Bearer会话，服务端加密保存AgentContext及受限刷新凭证。
4. 实现access过期、refresh轮换/复用检测、登出撤销、机构切换、刷新互斥和认证上游故障处理。
5. worker通过稳定auth_session_id/family_id读取/刷新身份，token轮换不改变任务引用；客户端和worker刷新共用CAS/single-flight，logout撤销family并增加auth_epoch。权限变化停止旧run，不能更换owner_hash继续；共享会话的临时签名过期不能导致校验被跳过。
6. 公网入口拒绝混用Cookie/Bearer/显式AgentContext；服务端再注入已验证的签名身份。保留浏览器原有CSRF流程。
7. 把认证错误映射为移动端可恢复401/403；禁止把秘密写日志、指标、队列正文。

**拟新增：** app/infrastructure/mobile_auth.py、app/api/routes/mobile_auth.py。**修改：** app/api/routes/auth.py中间件装配、app/main.py、app/core/config.py。上游认证端实现位置根据真实业务登录服务确定，不能虚构core gateway已经签发移动会话。

**完成标准：** 小程序/App同一用户可访问同一授权范围；伪造用户/机构失败；撤销后新调用及后台提交被阻断；原网页认证回归通过。
