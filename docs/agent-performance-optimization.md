# Agent 性能优化与版本回退规范

本文记录健身 Agent 的性能优化基线、质量门禁和回退方式。性能优化必须做到“可测量、可比较、可回退”，不能只凭单次响应速度判断是否上线。

## 当前基线与已验证优化

固定测试问题：`我今天适合做哪些热身动作？`。测试使用本地 BGE-M3 Embedding、本地 BGE Reranker、当前知识库和同一组织管理员身份；请求只读，不创建业务数据。

| 版本 | 变化 | 总耗时 | 输入 Token | 路由/状态 |
| --- | --- | ---: | ---: | --- |
| 基线 | 首次请求直接加载本地模型 | 19.22s | 18,908 | FITNESS_COACHING / COMPLETED |
| 预热版本 | 启动阶段加载本地 Embedding/Reranker | 9.42s | 18,991 | FITNESS_COACHING / COMPLETED |
| 当前优化版本 | 预热 + Schema 元数据压缩 + RAG 父上下文有界截取 | 8.53s | 10,685 | FITNESS_COACHING / HTTP 200 |

当前两个性能提交是独立的：

- `58bda6f`：预热本地检索模型，首请求不再承担模型加载。
- `afb0421`：删除不参与校验的 Tool Schema 展示元数据。
- `891d508`：保留 Top-K、权限过滤和 Reranker，只限制注入 Prompt 的超长父章节，并围绕命中 chunk 截取。

优化前基线已用不可变标签保存：`agent-perf-baseline-20260904`，指向提交 `98dbad2`。该标签只保存代码版本，不包含本地 `.env` 或 IntelliJ 真实密钥。

## 采用门禁

每个优化必须单独提交，并使用同一批固定问题比较：

1. `make agent-eval`：RAG 召回率、MRR 和越权命中不能下降。
2. `make agent-check`：Lint、格式、类型检查和全量单元测试通过。
3. 真实只读回归：HTTP 成功、路由正确、工具白名单正确、回答非空，记录输入/输出 Token 和耗时。
4. 安全相关回归：权限拒绝、确认中断、工具误选、模型失败不能被优化绕过。
5. 需要访问本地 PostgreSQL、ClamAV 或其他依赖的门禁，必须在依赖可访问时真实执行；环境不可访问只能记录为未完成，不能改成 Stub 后宣称通过。

“效果一样”在工程上指业务能力边界、召回权限和工具安全约束不变；LLM 每次自然语言措辞不保证逐字一致。若答案完整性、引用正确性、权限边界或工具选择下降，当前优化版本不采用。

## 企业生产做法

生产发布会同时关联以下版本，而不是只记录一个 Git 分支：

- 代码提交、容器镜像和配置版本；
- Prompt、模型名称/版本和模型参数；
- 知识库版本、文档版本和索引构建版本；
- 评测集版本、阈值版本和 Trace/评测记录。

发布时先离线评测，再进行小比例 Canary。观察错误率、P95 延迟、Token/成本、召回指标、答案完整性、安全拒绝率和工具误选率；全部指标达到门禁后才扩大流量。数据库迁移必须保持向前/向后兼容，不能把代码回退和数据库回退混成一个不可逆动作。

## 回退方式

本地验证某次优化不合格时，优先使用 `git revert` 回退对应提交，保留审计历史；不要用 `git reset --hard` 覆盖工作区。若要临时复现优化前版本，可基于基线标签创建临时分支：

```bash
git switch -c codex/agent-perf-baseline-check agent-perf-baseline-20260904
```

正式环境由发布系统切回上一份不可变镜像和配置版本，并重新执行健康检查、Smoke、权限和数据兼容性检查。回退完成后继续保留失败版本的 Trace 与评测记录，用于定位是延迟、Token、召回还是答案质量导致拒绝发布。
