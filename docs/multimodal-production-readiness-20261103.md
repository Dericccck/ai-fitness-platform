# 多模态功能上线门禁

本文记录本轮实现后的边界；不能用本机测试身份或单次模型回答代替生产验收。

## 已实现的保护

- 发送模型前按实际网关字符上限预算问题、上下文与知识，并对多图标注素材 ID。模型未给出局限时由服务端补充保守说明。
- 训练资料类型在向量及关键词召回前过滤，仍执行原有知识权限校验。只有实际提供的知识可被引用。
- 新产生的多模态历史会将上下文中的素材依赖传递到新回答；素材删除时现有删除逻辑会同时隐藏直接和记录到的间接依赖。该传播不重建部署前已有报告的历史依赖，也不能撤销第三方已接收的数据。
- 活跃素材按稳定账号主体限制数量和声明容量，上传幂等重试不重复占额。新增 `AGENT_MULTIMODAL_UPLOAD_MODE=gateway`：上传由服务端中转，数据库为每个上传任务持久记录至多一次应用级 OSS 写入调用；上传请求大小、接收时间和单进程并发均受限。生产环境启用多模态时必须选择 gateway。其他环境仍可选 direct，direct 的签名在有效期内可重放。
- gateway 模式下用户预览通过携带登录凭证的服务端接口读取，支持视频单范围请求，逐块检查会话和素材状态，不向客户端发送 OSS 签名 URL。客户端已接收或缓存的内容和模型供应商已获取的素材不能被撤回；电脑 Web 模拟会在内存加载整个预览文件，实际 App 仍需真机验证。
- 消息和会话支持分页；前端支持加载历史和查询失败后的有限退避重试。
- 已实现同一账号、同一机构的旧多模态会话自助恢复代码和 App 入口，但该功能默认关闭。服务端锁定会话并在同一事务中核对归属、重加密消息/报告/任务数据，再变更相关记录的归属；运行中任务、未完成删除、未失效的上传凭证、无法解密或不一致的数据均会阻止恢复。恢复操作支持重复提交和分页查找，不会迁移跨机构数据或旧文本 checkpoint。
- 自助恢复成功和重复提交在同一事务写入伪名化审计；已知拒绝结果单独记审计，审计写入异常会记录固定错误类别。审计不存消息、素材或原始会话编号，默认保留 90 天并由 Worker 分批清理；这一审计不替代正式身份撤权策略。
- 已实现动作报告与本人已发布训练计划的具体动作的可撤销关联，可只读查询该训练日已有的完成／跳过记录；训练服务对计划访问仍是权威，每次读取关联时再次授权。关联不将模型建议写入计划或训练实绩。页面可分页选择当前机构中本人可访问的已发布计划，也可按编号查询；计划列表按编号降序排列而非按发布时间排序。功能由 `AGENT_MULTIMODAL_TRAINING_LINKS_ENABLED` 控制，默认关闭；需先执行 0060 迁移、部署更新后的训练服务和 Gateway、接入可信身份并完成隔离联调。
- 素材删除在对应任务状态已过期时，仍按已记录的素材依赖清理保留消息和报告。旧数据可用 `python -m scripts.repair_expired_run_media_lineage` 默认只读统计候选；显式 `--execute --operator <标识>` 才会对符合条件的历史记录清除密文并记伪名化审计。操作员标识是调用者声明，不是身份认证；应以受限数据库账号、审计日志、备份和受控运维流程执行。本次未对真实数据执行修复。
- 清理积压时 Worker 加快处理；多模态 API 启用但无可用 Worker 会告警。生产需配置可达的 Prometheus 目标和真实值班接收器。
- 已增加独立的知识图片／视频解读契约和 App 选择入口；新模式默认关闭。先将新版本部署到全部多模态 Worker，确认旧 Worker 已排空并停止后，再在 API 设置 `AGENT_MULTIMODAL_KNOWLEDGE_ENABLED=true`；需同时发布支持知识报告的新客户端，旧客户端不支持该报告格式。新任务使用独立的加密投递、来源校验和相同的素材删除依赖。旧动作分析请求的幂等摘要保持不变。此开关只控制新任务的受理，关闭开关不会取消已经受理的任务；回滚前须停止受理、排空或安全取消知识任务，并确保旧客户端不会读取新报告格式。

## 仍未达到的上线条件

1. **正式认证与历史归属**：接入实际可信身份签发及撤权上游；现有 owner 摘要仍包含角色和权限。现有自助恢复是对同账号、同机构多模态会话的保守补救，不等于稳定归属架构：再次变更权限仍可能需要恢复。绑定了旧文本会话、含未知标题密文、数据不一致、超出处理上限或缺失旧密钥的会话不会被自动迁移。此前签发的上传凭证可能仍有效，恢复会等待上传会话到期再额外等待 5 分钟，即使该上传已经完成。恢复依赖可信上游可靠区分账号与机构，需在正式身份系统上验证角色变化、令牌撤销、账号停用、多账号及跨机构边界；短期旧令牌的撤销时效仍取决于上游和会话刷新机制。

   自助恢复可能让降权后的用户再次看到高权限时期生成的内容，当前数据未保存足够的权限来源来逐条判定是否仍可访问。因此 `AGENT_MULTIMODAL_OWNER_RECOVERY_ENABLED` 默认为 `false`，接口和入口均默认关闭。仅在数据归属政策明确允许、正式身份和撤权边界验收通过后，才可在受控环境显式开启；若政策要求按旧权限撤销历史内容，不能开启现有实现，必须先实现逐条授权与审计。
2. **历史素材依赖**：修复工具仅覆盖数据库中已明确记录的依赖、素材已经删除且任务记录已过期的历史数据。部署前报告仍可能没有完整的可追溯依赖，缺失的依赖不能凭空恢复；仍需根据产品与隐私策略评估处理范围，不要声称旧报告已经全部得到传递删除保障。
3. **上传部署与恢复**：gateway 是有状态的单次写入方案，不对结果不明的 OSS 写入自动重放；失败后应检查状态，必要时清除待发送记录并新建素材。需评估临时磁盘、流量和并发容量，配置云侧预算及告警，并在真实 OSS 和真实客户端进行故障演练。切换 direct 到 gateway 时，旧签名在有效期内仍可能使用，切换前需停止签发并等待全部旧凭证失效。回滚时也不能重新为已开始的 gateway 任务签发直传凭证，应等待或清理在途任务；生产禁止回退到 direct。数据库需要先执行 0058 迁移。电脑浏览器模拟的服务端 CORS 需允许 PUT 和 Authorization；小程序暂不实施。
4. **删除撤权与隐私**：gateway 预览逐块检查授权，但无法收回已经传出的字节；应用内隐藏和 OSS 物理清理仍是异步的。模型服务使用的短期 OSS 地址和此前已签发的地址仍有各自的有效窗口。原视频可能含音轨，媒体可能含位置等元数据；需要明确隐私政策、第三方处理范围、保留期及可选的净化方案。
5. **真实业务与客户端**：本人计划、动作及训练日记录的只读关联已实现，但仍需正式认证与训练服务联调；未实现从报告直接写回训练计划或执行记录。旧文本仅有限只读关联。原生 App 的应用标识、签名、隐私披露、弱网和真机测试尚未完成；微信小程序未开发。
6. **效果与运行**：需要人工标注的动作数据集、视角与弱质量覆盖、风险样例和持续评估；需要容量、成本、故障恢复、部署回滚和告警到人的演练。现有模型成功响应不代表动作判断准确。
7. **知识素材解读验收**：新增路径已通过模拟模型及隔离数据库测试，尚未用真实模型和知识素材完成质量验收。解读只声明使用画面，不保证识别全部文字或理解音轨；用户上传的原视频仍可能包含音轨。真实联调前不要启用生产开关。

动作评估新增离线汇总工具 `python -m app.evaluation.multimodal_review <labels.json>`：仅接收人工复核后的匿名枚举标签，不读取素材、用户问题或模型回答；分别统计明显问题漏判、误报、证据不足却给出确定结论、请求失败及人工标注的不安全建议，并按图片／视频和可见性分组。它不生成标注，也不把缺少样本视为零风险；需要有授权的真实样本、独立复核和事先确定的门限才能用于上线决策。

输入示例（示例仅用于说明格式，不是评测数据）：

```json
{"cases":[{"case_id":"sample_01","media_kind":"video","visibility":"limited","reference":"insufficient","assessment":"INSUFFICIENT_EVIDENCE","unsafe_advice":false}]}
```

当前本机临时联调运行器与正式 Worker 不是同一运行方式，且连接真实 OSS；不要假定其具备正式 Worker 的全部到期清理与租约回收能力。不要在未核实数据保留意图前清空现有数据库或删除 OSS 素材。

可通过 `AGENT_DATABASE_URL` 明确选择数据库后运行 `python -m scripts.audit_multimodal_history --execute`，工具使用只读事务并只输出汇总数量，不输出账号、素材或对话内容。归属分裂数与可能缺少历史依赖的报告数仅用于评估迁移范围；候选不代表已确认缺失，不能据此自动删除数据。

恢复查询的索引由 `20261104_0059` 增加：普通 PostgreSQL 索引构建会阻塞相关表的写入，大表部署应先评估耗时并安排维护窗口。先迁移再部署使用恢复功能的新版本；索引不改变数据，不会主动恢复或删除任何用户会话。回滚应用前应评估已经恢复的会话与旧客户端兼容性。真实身份服务、网络故障和多实例并发仍需在隔离的类生产环境验收。

新版本还依赖 `20261104_0060` 迁移，应用前应备份并先在隔离环境演练。回滚此迁移会删除关联及审计表，不能作为保留数据的普通应用回滚；先导出并按数据保留要求处理，确保无新代码访问这些表。
