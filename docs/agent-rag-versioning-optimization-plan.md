# Agent 与 RAG 版本治理优化计划

更新：2026-09-05。状态：第 1 批 P0 已实现、迁移已应用并通过本地回归；第 2 批已补 v2 Manifest/Trace 关联基础，并已要求预发布/生产清单绑定索引构建版本；真实流水线接入和真实评测库验收仍未完成。

目标：修复知识发布正确性，建立可追溯、可评测、可回退的发布组合，再用真实数据优化响应速度、Token 和存储开销。
本计划以当前代码核对结果为准；此前讨论中的建议不自动视为已实现功能或已经证实的线上故障。

## 1. 现状核对与必要修正

| 项目 | 当前证据 | 下一步 |
| --- | --- | --- |
| 发布清单 | `scripts/release_manifest_check.py` 已兼容 v1，并可生成/校验 v2 组件摘要；`scripts/build_release_components.py` 已能从真实模型文件、Prompt 和 Tool Schema 生成组件摘要；TruLens 已使用正式评测发布描述校验数据集/阈值摘要；预发布/生产 v2 清单缺少 `index_build_id` 时会失败即停 | 将组件生成器接入流水线，注入实际模型制品、索引构建 ID 并生成正式 v2 Manifest |
| Trace 版本 | `app/evaluation/telemetry.py` 已记录代码、Prompt、图、知识库及 release/Manifest/build/eval 关联键 | 绑定实际内容摘要与索引构建 ID，并补真实 Trace 验收 |
| TruLens | 路线图已有 2026-09-01 独立 PostgreSQL 真实导出验收记录 | 复验当前运行配置、写入读取和账号权限；历史成功不等于本轮通过 |
| 文档去重 | `ingestion.py` 先按 source_uri 查已发布文档，再比较 checksum | 拆分内容变化、发布元数据变化和索引策略变化 |
| 来源身份 | 已增加文档 owner、机构/可见范围条件及来源作用域索引；旧 PRIVATE 数据可无歧义回填 | 仍需真实 PostgreSQL 碰撞/并发验收和稳定来源 ID 设计 |
| 重建 | `reindex_service.py` 从原件重解析，force=True，按文档原地替换 | 增加不可变构建、全库切换和恢复能力 |
| force 行为 | force 绕过未变化跳过，但不绕过同版本 checksum 冲突 | 解析器改变 checksum 时，同文档版本重建可能冲突；需单独索引版本 |
| 事务 | `replace_document()` 提供单文档原子替换 | 不等于整个知识库原子换模型；批量原地换模型期间可能混合新旧向量 |
| 检索 | SQL 带发布状态、范围和角色等条件，再融合重排 | 保留 SQL 权限边界，实测 ANN 在过滤条件下的召回率 |

补充边界：哈希本身不会提供权限隔离；“同来源去重符合治理方向”不等于现有来源授权实现已覆盖所有边界。
增加查询 LIMIT 不保证 ANN 内部搜索扩大；过滤前候选数也不是当前 SQL 可直接返回的指标，不能虚构统计。
强制重建不会自动迁移 pgvector 维度，也不会自动保留上一套模型向量以供回滚。

## 2. 固定开发顺序

### 第 1 批：知识发布正确性与并发控制（P0）

交付内容：

- 采用服务端确定的来源所有权（平台/机构/私有所有者）和稳定来源 ID；先检查旧数据来源碰撞，建立可审计迁移映射。
  可见范围作为发布属性管理，不能仅靠用户输入 knowledge:// 路径实现隔离；改变所有权必须单独校验。
- 查询、版本分配、归档、发布、重试和重建使用同一来源身份约束；组织管理员不能覆盖或归档其他机构及平台来源。
- 保留当前解析 checksum 用于兼容；增加规范化的 publication_fingerprint，覆盖角色、组织/所有者、可见范围、有效期及文档属性。
- 正文、发布属性、索引策略都不变才跳过；仅 ACL/有效期变化时经审核原子更新文档和切片元数据，并保留审计。
  若标题等属性参与实际嵌入输入，则按输入变化处理，不能一律按“只改元数据”处理。
- 上传增加有作用域的幂等键：同键同参数返回同任务，同键不同参数返回冲突；不同上传键不强行共享其他用户的审核任务。
- 发布时以预期当前版本做并发校验，防止两个待审任务互相覆盖；用短事务锁或条件更新和数据库约束保证唯一当前版本。
  Embedding 调用不持有长数据库锁。
- 老重建任务执行前后复核当前版本、原件哈希和审核证据；不能恢复已下线来源或覆盖较新发布。
  为中断任务明确租约、恢复、重试和终态语义，不能将进程崩溃自动描述为已持久化 FAILED。

验收：跨机构同 URI、全局与机构同 URI、不同私有所有者、重复上传、权限收紧/放宽、并发发布、旧任务晚到、原件篡改、Embedding 失败。
必须验证没有未授权返回或覆盖；权限更新不能被 checksum 跳过；失败不破坏原有效版本。涉及 SQL 约束用隔离 PostgreSQL 集成测试证明。

### 第 2 批：发布指纹和观测关联（P0，依赖第 1 批）

- 扩展已有 Release Manifest，增加 schema v2，兼容现有校验和回退脚本。
- 对 Supervisor、四领域 Prompt 模板及实际影响行为的静态指令生成确定性摘要；保留人工可读版本名。
  用户输入和动态检索正文不进入公共 Prompt 摘要。
- 配置摘要只包含经过白名单审核的非敏感有效参数，并规范化默认值；密钥不保存值或普通 SHA，使用 Secret 引用版本/kid。
- 本地 Embedding/Reranker 制品摘要覆盖模型权重、Tokenizer、模型配置和预处理设置；`build_release_components.py` 在制品准备/构建时一次性遍历并核验目录，输出只含摘要、文件数和字节数，不能每个请求遍历大文件。
- 记录工具 Schema 摘要及兼容测试。不兼容修改才升级工具主版本，不为“补版本”盲目将所有 v1 改成 v2。
- 固定 eval_release_id，绑定评测集、阈值、评分器代码、Judge Prompt、Judge 模型/参数；当前已有 `evals/trulens_smoke.release.json` 和 Judge 发布描述，CLI 会校验路径及 SHA-256 摘要；缺失必需指标应失败，不能自动通过。
- Manifest 关联代码、依赖锁、镜像、图、Prompt、非敏感参数、模型、工具和评测制品；索引构建 ID 先预留，待第 3 批接入。
- Trace 根节点及评测 Record 关联 release_id/manifest_digest；模型 Span 记录实际模型，检索 Span 记录实际 build_id、文档 ID 与版本。
  只有文档版本数字“1/2”不足以唯一定位引用；大清单存制品库，避免每个 Span 重复附加。

验收：相同输入得到同摘要；任一关键制品变化可追踪；清单不含密钥或个人正文；Trace 到 Record 能恢复版本组合。
复用 trulens-postgres-check、trulens-agent-runtime-check 补当轮真实证据；缺环境时列出未执行项，不替代为模拟通过。

### 第 3 批：独立索引构建与原子切换（换模型前必做）

- 文档业务版本和索引构建版本分离。来源内容不变而模型/切片策略变化时生成新 build_id，避免复用文档版本触发 checksum 冲突。
- 建立构建主表、文档快照/明细及构建可查询状态；保存原件哈希、解析策略、切片策略、模型摘要、维度和文档集合。
- 新构建进入隔离的候选存储；采用经过迁移和索引验证的独立表/分区方案兼容不同维度，禁止把新模型向量写进仍在线的旧模型集合。
- 按知识库及权限边界维护生效构建指针；查询开始时固定 build_id 和对应查询模型，向量与关键词召回使用同一构建。
- 未完成/失败构建不能启用。构建完成后先影子评测，再通过原子切换启用；请求中途不能切到另一套模型。
- 构建期间新上传通过增量补齐与切换前校验纳入；权限撤销/下线实时以当前授权为准，旧快照不能恢复已撤销访问。
- 保留上一套索引及可加载模型制品，验证回切；回滚索引不回滚用户权限，也不回滚 Java 业务事实。
- 统计可重建覆盖率，列出缺原件或没有成功上传任务关联的历史文档，不能把这些文档默默漏掉后宣称全库完成。

验收：同维不同模型拒绝混用、不同维度隔离、半批失败、中断恢复、构建期间发布/撤销、整库切换、切换中请求、旧版本恢复。
上线前先迁移演练和备份；保留旧读取路径兼容，直到新路径和回切全部通过。

### 第 4 批：固定四领域基线和整链路评测（依赖第 2/3 批）

- 复用现有评测集，增加重复上传、权限更新、旧版本过滤、模型构建切换等 RAG 用例。
- Fitness：通用热身知识、个人信息不足、来源引用和安全前提；Booking：正确工具、无结果、权限拒绝和确认；
  Operations：指标口径/时间范围、工具误选及故障；Customer Service：制度知识与工单写入确认边界。
- 真实只读运行固定文档快照、用户权限、模型参数和题集；写入/确认流程先在隔离测试环境验收。
- 与精确检索参考比较 Recall@K/MRR，核对答案完整性、引用、工具选择、确认和越权；多次运行记录分布而非只报一次结果。
- 同时记录端到端延迟、LLM/Embedding/检索/Reranker 分段耗时、输入输出 Token、错误率、冷启动和预热差异。

门禁：未授权返回、未经确认写入、错误索引切换零容忍；其余质量指标不得出现经重复验证的退化。
基线、候选使用相同评测发布；缺指标视为未验收。具体性能预算由本轮测量确定，不提前承诺固定秒数。

### 第 5 批：受测量约束的性能优化（依赖第 4 批）

- 检查实际 pgvector 版本、数据规模、过滤选择性和 EXPLAIN 执行计划；用不同租户/角色分布模拟严格过滤。
- 在版本支持时比较 HNSW 搜索参数及 iterative scan；候选不足时允许有时间/规模上限的扩展或精确查询，仍在 SQL 内执行完整 ACL。
- 记录数据库返回的有效向量候选数、关键词候选数、融合/重排/引用数和空召回；不向普通用户暴露未授权数量，不伪造 ANN 内部过滤前计数。
- 对照实测决定是否增加发布状态索引、分区或可检索集合；不能仅因 JOIN 存在就复制状态字段，新增字段必须有事务一致性设计。
- 测试重复父章节合并和来源多样性，保留多段共同支持同一答案的情况，不盲目硬限制每文档 Chunk 数。
- 延续已验证的模型预热、工具描述压缩和父上下文限长；再按 Trace 判断是否优化串行调用、工具参数及 Prompt。
- 需要改善等待体验时单独评估流式输出；流式首字提前不等于总耗时下降。最终计划与确认卡片仍基于完整校验结果。

验收：每个候选参数独立比较和提交，安全及质量门禁通过后才采用；输出 P50/P95、Token、召回和失败率证据。
线上遥测异步有界，观测开销纳入测量；业务必需安全审计继续保持现有一致性要求。

### 第 6 批：历史数据与重复提醒（P2，按体量触发）

- 先展示历史构建、归档 Chunk 和原件空间占用，支持清理预览；确定保留窗口后再实现限批清理。
- 保留活动构建、回滚构建、运行中请求/任务及审计所需引用；清理不能先删原件导致无法重建，回滚窗口结束也不等于可删除全部审计。
- 精确重复提醒仅限管理员有权查看的范围，不泄露其他机构是否存在相同文件；语义相似仅提示人工判断。
- 有明确存储收益再做对象共享/引用计数；共享物理对象不能共享授权或删除权。暂不增加共享向量架构。

## 4. 提交、验收与收口

每批交付代码、必要迁移、中文状态说明、针对性回归和规划状态更新；按风险拆为可回退提交。
完整 make agent-check 在相关集成完成后执行；数据库/TruLens/性能测试记录真实环境和实际结果。仅文档变更做差异和链接检查。
禁止将本地 .env、IDE 密钥配置或敏感摘要纳入提交；提交清单仅包含本批明确修改的文件。

开发可在本地完成；正式认证、生产负载和生产回滚的证据仍需要对应环境，不能因本地验收成功标记生产验收通过。
Linux/GPU OCR、短信、Push、人工转接、图片动作框选和复杂训练扩展继续按用户决定排除。

当前下一步固定为第 2 批剩余工作：把真实流水线模型制品摘要、索引构建 ID 和正式 v2 Manifest 接入部署产物，并补 TruLens 在线接收/Trace 到 Record 的真实验收；评测发布号已通过描述文件接入 CLI/Makefile/CI，预发布/生产缺少索引构建版本时已失败即停。第 1 批的真实 PostgreSQL 并发场景随后补齐。
第 1—5 批达到门禁即结束本轮核心优化；第 6 批按数据量和保留政策安排，不无限扩展业务功能。
