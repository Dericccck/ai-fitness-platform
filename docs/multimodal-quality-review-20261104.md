# 健身动作分析质量复核方案

状态：准备实施，尚无专业审核结论。此方案针对当前多模态动作分析；知识资料解读、生产部署和真实账户验收不能由它替代。

## 已知问题与临时控制

2026-11-04 的本机知识检索发现，多段资料针对弓步蹲或单腿蹲使用了“膝关节不要超过脚尖”的表述，而模型把类似表述推广到了普通深蹲建议。无知识库的同素材对照没有出现同一句建议，但每种条件只调用一次，模型输出存在随机性，不能据此断言唯一原因。相同对照中模型还对膝盖内扣、足弓、肌肉控制等作出需要人工核实的判断。后续检查确认，剩余召回片段也包含“有效保护膝关节、预防运动损伤”表述，真实模型在一次单独追踪中重复了这一说法；单次追踪不能证明因果。

当前在两条多模态路径的知识检索结果中隔离命中已知膝／脚尖绝对化表述和“预防损伤／有效保护关节”等规则的分块；动作分析模型结果若命中这些有限规则，将整份报告替换为无法可靠评价的提示，不向用户展示局部建议。提示词同时要求区分可见证据和推测。这些规则会漏掉其他表达，也可能误拦截正常讨论，**不是专业审核、医学判断或安全保证**。知识库原始记录未删除；隔离不等同于已经修正资料。仅命中项被剔除时，报告中的 `knowledge_status` 反映剩余可用证据。

此次提示词的默认版本号更新为 `movement-analysis-v2`。API、Worker 及模型用量记录必须使用一致的配置；如果环境显式设置了 `AGENT_MULTIMODAL_PROMPT_VERSION`，应同步更新，避免将不同提示词记录为同一版本。环境变量本身不会自动校验代码和版本标签是否匹配。

上述输出控制只应用于更新后新生成的动作报告，不会追溯修改或屏蔽历史报告、历史消息或已经送达的内容。正式开放前应审查历史内容的访问处理和提示方式；不能声称历史内容已通过新规则检查。

在同批四个公开深蹲视频的最新真实模型复验中，四份报告均触发规则并被整体降级为无法可靠评价；本次不是专家盲评，也不能把拦截计为模型判断正确。当前规则可能影响正常回答和用户体验，需要核查触发原因、由专业人员复核，并用更大且独立的样本确认误拦截及漏检。真实 OSS 测试对象各版本已清理。

随后抽查一条样本，模型重复了剩余片段中的保护关节和预防损伤说法，触发输出降级；扩展知识分块隔离后，对同一视频又调用一次，原查询返回的 5 个分块全部被隔离，报告显示 `knowledge_status=EMPTY`，这次生成了未见明显问题的报告。该报告及动作观察未经专家复核，不能认为判断准确；这次调用也不能代表对其他视频或全部模型输出有效。两次追踪的 OSS 对象版本均已清理。

## 资料审核

1. 导出实际被拦截的资料版本、分块、上下文和来源，由有资质的健身或运动专业人员判断适用动作、人群、使用条件及可能过度推广的内容。不得把资料中针对特定场景的建议直接改写成对所有人的结论。
2. 经授权的资料编辑人依据审核意见，在知识管理流程中提交修订版本，保留来源、版本、审核人、审核意见和适用范围。需要临床判断的内容交由相关专业人员审查。
3. 在独立环境中重新索引，并检查检索结果、权限和引用；经复核后再决定是否缩小或移除相应临时隔离。禁止仅因模型回答变得流畅而撤除保护。未完成审核前维持当前隔离。

## 样本及评审

1. 预先固定动作范围、各类风险、样本数量及验收阈值；覆盖图片和视频、常用动作、不同参与者、视角、遮挡、光线与清晰度，以及足以判断和证据不足的情形。测试集按参与者划分，禁止把同一视频或同一参与者的不同视角同时放进调优集和保留验收集。
2. 按文件哈希核对重复、冲突和损坏样本；保留来源、许可、授权用途以及是否允许发送至当前模型服务的记录。收集真实用户素材须另有明确授权和处理规则。先前发现一对不同标签但字节完全相同的视频，不能当作评估标准答案。
3. 由两位具备相应能力的独立审核人员先看素材，记录可见／不可见部位、可观察问题、证据不足、严重程度及参考依据；意见不一致交第三人裁定。不要把单个 `good/bad` 标签视为具体动作问题的金标准。
4. 固定模型版本、提示词版本、知识库版本、开关和提问；先盲评模型回答，再揭示标签。逐条评估观察是否可见、建议是否适当、引用是否支持建议、限制说明是否充分和是否存在高风险建议。模型自己给自己打分不能替代专家复核。
5. 汇总明显问题漏判、正常动作误报、证据不足时给确定结论、模型／系统失败及不安全建议，按动作、素材、视角和可见性分组；每项提供分母、未解决数和抽样局限。无对应样本时指标为不可计算，不可当作零风险。严重不安全建议须逐例复核并处置。

现有 `python -m app.evaluation.multimodal_review <labels.json>` 仅汇总已由人工复核的匿名标签，不执行人工复核或发布判定。输入格式例如：

```json
{"cases":[{"case_id":"case-001","media_kind":"video","visibility":"limited","reference":"insufficient","assessment":"INSUFFICIENT_EVIDENCE","unsafe_advice":false}]}
```

示例不是实际评审结果。视频、用户问题、模型回答、身份信息和任何凭证不得写入这个汇总输入；原始材料和更详细的审核记录应保存在授权的受控位置。

## 上线决策

专业负责人、产品负责人及安全负责人应在观察保留测试集结果前确定可接受阈值，并签署资料与动作评估结果。任何关键组样本不足、严重问题未处理、无独立审核、无素材许可或无法复现的情况都不能视作通过。模型、提示词、知识库、检索策略或报告规则变更后，应重新运行相关回归并按变更范围评估是否需要再次专家审核。
