# 多模态动作分析：当前实现与验收状态

截至 2026-11-03。本文件记录代码与验收边界，不表示已经生产上线。原设计与执行计划见同目录的多模态方案文档；接口以当前代码和 OpenAPI 为准。

## 已实现

- 独立 Expo App：登录、会话、图片/视频选择、上传、任务进度、历史、报告、删除、失败提示及显式恢复。模型或 OSS 密钥不进入客户端。微信小程序不属于本次范围。
- 服务端移动端认证代理、短期访问令牌和刷新轮换、会话撤销；可信身份仍由上游认证服务提供。
- 私有 OSS POST 直传策略、版本绑定、上传完成后的格式与元数据验证、私有短期读取地址；素材直接作为图片或视频发送给多模态模型，不在项目里抽帧或运行人体骨架识别。
- 持久化分析任务与幂等、后台租约与恢复、用户/素材权限和版本检查；结果结构、引用和来源校验，加密保存消息与报告。
- 删除请求使关联内容不可访问，并排队执行 OSS 对象版本清理；上传凭证有效期后还会再次清理，以覆盖晚到的写入。后台还会将到期素材纳入同一删除流程。
- 同一多模态会话可读取已授权、未删除的近期对话摘要；已启用个性化时复用现有 Memory 服务提供的沟通偏好，限制机构和主体范围。记忆版本变化后不会重放旧上下文，分析中途变更也会阻止发布；已经发送给外部模型的请求不能撤回。App 可列出同一授权范围内已完成的旧文本会话并显式关联，读取最近六条可安全使用的文本作为分析上下文；两套存储不自动合并，也不会把多模态报告写回旧 checkpoint。
- Redis 共享模型并发租约和 UTC 每日调用次数上限、单次请求总时限及可配置启用的调用用量账本；调用次数限制不是精确货币预算。Worker 提供指标、告警规则与可选 Compose profile。
- 到期未完成上传及其可能留下的最终版本可进入删除队列；成功上传的暂存对象在上传凭证到期后单独清理。生产模式提供独立无网络解析容器，通过 Unix socket 与 API 交互，媒体卷只读，容器无服务密钥且启用只读根文件系统、资源限制及非 root；镜像提供 `ffprobe`。
- 预设模型 `qwen3.7-plus-2026-05-26`；这是可配置项，不代表当前账户已开通或质量已经通过项目评估。

## 已验证

- 隔离 PostgreSQL/Redis 和模拟认证、存储、模型的多模态、迁移及监控相关专项测试 61 项通过；后端全量测试 993 通过、57 跳过。告警规则通过 Prometheus 校验和单元测试，Compose 配置通过静态校验。
- App TypeScript、前端测试和 Expo Web/iOS/Android JS 打包通过；lint 通过。
- 在桌面网页模拟 App，使用公开健身图片和视频，完成实际文件上传、媒体验证、任务调度、模拟执行、消息和报告页面展示。模拟执行器会读取文件，但不会调用模型，报告明确标注不能判断动作。
- Linux 非 root 容器内使用实际照片和视频验证了解析进程；数据库新迁移经过隔离库升级、降级和再次升级。
- 无网络、只读根文件系统和只读素材卷的独立解析容器已在 Linux 环境中用实际图片和视频验证，解析服务不可用时上传验证可重试。
- 本机联调运行说明见 `fitness-mobile/README.md`。模拟存储在进程内存；数据库和 Redis 为隔离测试容器，不是 OSS。

## 真实接入仍需的条件和工作

1. 在服务端密钥管理中配置百炼 API Key、兼容多模态接口地址、已开通的模型；配置 `AGENT_MULTIMODAL_API_KEY`、`AGENT_MULTIMODAL_BASE_URL` 和相应模型设置。不要把密钥放进 App 或聊天。
2. 提供启用版本控制的私有 OSS 桶、地域、HTTPS endpoint 和最小权限身份，配置 `AGENT_MULTIMODAL_OSS_ENDPOINT`、`AGENT_MULTIMODAL_OSS_BUCKET`、`AGENT_MULTIMODAL_OSS_REGION`、`AGENT_MULTIMODAL_OSS_ACCESS_KEY_ID`、`AGENT_MULTIMODAL_OSS_ACCESS_KEY_SECRET`，以及 `AGENT_MULTIMODAL_MEDIA_HOSTS`（允许的 OSS 域名列表）。需配置桶生命周期及用户数据保留策略，并核验跨域和真实供应商权限。
3. 提供符合现有接口的可信认证上游及服务凭证，配置 `AGENT_BROWSER_AUTH_UPSTREAM_URL`、`AGENT_BROWSER_AUTH_UPSTREAM_SERVICE_TOKEN`、网关上下文签名密钥/密钥环，以及消息加密密钥、PostgreSQL、Redis；完成数据库迁移，分别运行 API 与多模态 worker。启用 `AGENT_MULTIMODAL_ENABLED`、`AGENT_MOBILE_AUTH_ENABLED`、`AGENT_MULTIMODAL_API_ENABLED`。
4. 使用真实 OSS 与模型分别完成图片和视频调用、计费及签名 URL 可达性验收，并对有标注的样本评估质量、误判、低质量画面和安全提示；当前未做过真实供应商调用，不能承诺模型对任何动作判断准确。
5. 生产发布前仍需在真实基础设施上验证 OSS 版本清理和生命周期配置、Redis 持久化和非淘汰策略、所有 Worker 的配额配置一致性、监控告警、故障恢复、磁盘加密和费用；调用次数上限不能保证货币支出上限。隔离容器需在每个 API 节点本地部署，并由生产运行时的 seccomp、网络、主机和存储策略继续保护。旧文本和多模态消息仍是不同存储：关联只提供旧文本到多模态的只读上下文，不会自动写回或删除旧文本。
6. 真实 iOS/Android 设备、相册/摄像头权限、切后台、弱网、恢复、播放及安装包验收均未完成。本次按用户要求暂缓。

生产环境完整配置还需遵循现有服务配置校验和部署文档，勿直接照搬本机测试密钥或模拟认证。

生产部署与故障处理参见 `multimodal-operations.md`。
