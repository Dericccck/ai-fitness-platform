# PDF 解析专项第一轮质量记录

日期：2026-08-12

本记录对应开发路线中的“阶段 4.1：复杂 PDF 解析质量专项”。本轮只优化解析器和
回归测试，不修改 PostgreSQL 中已经发布的知识版本，也不把原始 PDF 改写成清洗后的文件。

路线调整（2026-08-15）：基础清洗、页面画像、质量门禁和前后版本比较器保留；剩余复杂 PDF 优化、
真实 OCR/视觉服务、专业标注和知识库重建延期到项目收尾阶段 12.1，不再阻塞 Booking Agent 及其他
健身业务 Agent 开发。

## 本轮完成内容

- 使用 `pdfplumber` 的文本层和原生表格坐标提取，尽量避免表格内容与正文重复入库。
- 过滤高置信度网页打印模板：无障碍导航、网站导航、搜索框、打印/关闭、版权和发布时间。
- 识别目录页及页码点线，避免目录标题列表进入语义检索。
- 对跨页重复且位于页首/页尾的页眉页脚去重；正文中偶然出现的同名标题不会仅因重复而删除。
- 使用 Unicode NFKC 规范化修复 PDF 常见兼容字符，例如 `⽆`、`⾼`、`⼀`。
- 保守合并中文换行、英文连字符断词和标点边界；标题、编号项、列表项和问句保持边界。
- 表格保留表头、页码、表格序号和行范围元数据。
- 增加网页模板、目录、中文页眉、表格噪声、中文换行和父节点边界单元测试。

## 尚未解决的风险

1. PDF 原始文本层已经缺字或错字时，清洗器不能根据猜测自动补写医学术语；例如抽样资料中的
   个别“常见/维持/运动前”等词存在文本层缺损，需要 OCR 或人工校对。
2. 当前表格提取已保留表头和行范围，但跨页同一张表的连续合并、列错位检测和表格质量阈值
   还需要在自动质量门禁中完成。
3. 当前标题识别采用保守启发式，英文长文和复杂多栏 PDF 仍需通过页级基线、父节点完整性和
   引用页码准确性评测后才能发布。

## 发布约束

本轮结果只证明“解析器第一轮改进可运行”，不等于知识库可以立即全量重建。到阶段 12.1 收尾重建前必须完成：

1. 解析质量门禁：噪声率、短碎片率、重复率、父节点完整性、表格完整性和缺失页阈值。
2. 与 `docs/rag-baseline-20260812.md` 中的 Recall@K、MRR、引用准确性做前后对比。
3. 只有通过门禁的资料才生成新的父子节点和 Embedding；失败资料继续人工审核或保持
   `REFERENCE_ONLY`。

## 解析质量门禁首次运行结果

执行命令：

```bash
make knowledge-quality-gate
```

本次门禁使用 `evals/document_quality_thresholds.json`，只读取原始资料并复用解析器、
父子切分逻辑，不写数据库。结果为：

- `PASS`：9 份，适合进入后续审核/索引流程；
- `REVIEW_REQUIRED`：4 份，主要是医疗或高风险资料，必须人工审核；
- `BLOCKED`：5 份，主要是扫描 PDF 缺失大量页面，必须先接 OCR 或更换资料；
- `REFERENCE_ONLY`：3 份，继续仅供人工参考。

这里的 `BLOCKED` 不是解析器崩溃，而是质量门禁主动阻止不完整资料进入知识库。当前最明确的
阻断原因是 WHO 指南缺少第 1、2、3、5 页，以及 4 份疾病指导原则缺少大部分页面。质量门禁
命令在存在 `BLOCKED` 或 `REVIEW_REQUIRED` 时返回非零退出码，不能被误认为可以自动发布。

## 图片密集型 PDF 及其他版式风险规划

当前门禁已经能发现“整页没有文本”的缺失页，但还不能仅凭文本提取结果判断一页是否主要由图片
承载知识。后续在知识库重建前增加以下检查和路由：

1. 逐页计算图片面积占比、文字密度、文字块面积和图注数量。图片占比高且文字稀少时标记
   `IMAGE_HEAVY`，即使页面存在标题或一两行描述，也不能自动认为内容完整。
2. 图片只包含文字时交给 OCR；图片包含动作示范、姿态、步骤或箭头说明时，增加视觉描述和动作
   结构化标注。视觉模型只生成候选描述，动作标准性、伤病风险和医疗结论必须人工审核。
3. 保留图片、图注、编号、箭头说明、相邻段落和原始页面区域之间的关系，引用不仅要能回到页码，
   还要能定位到必要的区域或图表编号。
4. 检测双栏/多栏阅读顺序、浮动图注、跨页表格、流程图、信息图和图表；无法稳定恢复时阻断自动
   发布，转人工审核。
5. 保存 OCR/视觉引擎、模型版本、页级/块级置信度和处理时间。关键数字、单位、医学术语或动作
   步骤置信度不足时，不能静默生成 Embedding。
6. 检查图片中的人脸、个人信息、二维码、第三方水印和版权来源；图片和图片描述必须继承原文档
   的组织、角色、有效期和审核状态。
7. 对 OCR 文本、原生文本、图片描述和动作标注做来源关联、内容哈希和版本追踪，避免重复召回，
   并支持模型升级后的增量重算、回滚和审计。
8. 检查低分辨率、旋转、裁切、模糊和异常图片；混合 PDF 按页面/区域合并 OCR 与原生文本，不能
   简单拼接造成重复。
9. 第一阶段只把经审核的图片描述转成文本进入现有 RAG，不直接引入多模态向量库；当图片成为主要
   检索对象时，再单独评估多模态 Embedding、权限、成本和删除回收流程。
10. 图片相关引用必须能回到原始文件、页码和图表/图片区域；OCR、视觉描述和人工标注应通过异步
    任务、幂等键、重试上限、死信和预算控制管理，不能阻塞用户请求。

这些规则会在“解析质量门禁”阶段完成后、知识库重建之前实现。这样可以区分：

实施顺序固定为：先做页面级图片/文字统计和路由标记，再接 OCR/视觉描述与人工审核，随后做权限、引用、
版本和去重校验，最后才生成父子节点、Embedding 并重建知识库。当前可以先实现识别和阻断逻辑，真实 OCR
和视觉服务接入后补齐识别能力，但不能绕过门禁直接把图片密集型页面发布为可检索知识。

当前无 Linux OCR 环境时先实现四种组合路由：`NORMAL`、`OCR_REQUIRED`、
`VISUAL_REVIEW_REQUIRED`、`OCR_AND_VISUAL_REVIEW_REQUIRED`。组合状态用于表达“图片中的文字需要
OCR，同时图片本身可能承载动作或姿态知识”；后续 OCR 成功只能解除 OCR 部分，必须保留教练/专业人员
视觉审核要求。路由阈值属于服务端部署配置，不接受上传者或 LLM 请求级覆盖。

```text
图片少、文字充分       → 正常文本/表格解析
图片多、文字少         → IMAGE_HEAVY → OCR/视觉处理 + 人工审核
图片承载动作知识       → 图片描述/动作结构化标注 + 教练/专业人员审核
版式顺序或图文关系不明 → 阻断发布，人工复核
```

## 页面画像与发布门禁实现结果（2026-08-13）

本轮在不依赖 Linux OCR 服务的条件下完成了页面级确定性检测：

- 使用图片/文字矩形并集计算面积，重叠对象不会重复计数，比例限制在 `0..1`。
- `ParsedDocument` 保存每页图片数、图片占比、原生文字数、文字面积、表格数、图注数、路由和原因。
- 纯图片页没有可索引正文时仍返回页面画像；上传可进入审核队列，但发布服务在 Embedding 前阻断。
- OCR 和视觉审核使用组合状态；OCR 成功只能解除 OCR 部分，不能自动解除专业视觉内容审核。
- 阈值由 `AGENT_RAG_PDF_*` 部署配置统一管理，上传者和 LLM 无法按请求放宽。

真实 21 份资料回归仍为：9 份 `PASS`、4 份 `REVIEW_REQUIRED`、3 份 `REFERENCE_ONLY`、5 份
`BLOCKED`。WHO 指南第 2 页需要 OCR，且仍存在 4 个缺失内容页；4 份扫描型疾病指导原则分别有
13 至 15 页需要 OCR，未被错误放行。它们的第 2 页包含“中国居民平衡膳食餐盘”信息图和完整正文，
被标记为专业视觉内容审核，而不是直接认定为健身动作审核。具体审核角色将在下一切片根据文档类型、
风险标签和页面内容分类决定；该工作已延期到阶段 12.1：动作/姿态交给教练，疾病、营养和高风险运动
建议交给具备相应资格的人员。

质量证据：Ruff 通过、Mypy 严格模式通过、Agent 服务 104 项测试通过。质量门禁仍按设计返回非零，
因为当前有 5 份阻断资料和 4 份需人工审核资料；这表示 fail-closed 生效，不是程序执行失败。

## 第二轮确定性噪声修复（2026-08-15）

本轮针对真实资料中发现的两类“解析器输入已经被污染”的问题做最小范围修复，不调整父子切分策略，
也不直接重建 PostgreSQL 中已经发布的知识版本：

- 部分演示文稿 PDF 的字体映射会把每个 ASCII 字符提取两次，例如
  `IInnffoorrmmaattiioonn`、`22nndd`。清洗器只折叠一个完整 ASCII 单词中“每一对字符都相同”的情况，
  因此不会破坏正常的 `coffee`、`letter` 或业务数字。
- 同一行已经确认存在上述重复字形时，才修复成对重复的句号、逗号和 URL 路径分隔符；正常省略号、
  URL 协议和英文双写字母不走这组规则。
- `pdfplumber` 偶尔会把多栏正文文本框误识别成只有一个多行单元格的表格。此类对象没有表头和行列
  语义，现改回正文文本路径；真正的多行多列表格仍保留表头、表格编号、页码和行范围。
- 表格单元格在转 Markdown 前也执行同一套规范化，避免正文和表格走两套清洗规则。

真实资料验证：`Physical_Activity_Guidelines_2nd_edition_Presentation.pdf` 的重复字形和重复标点残留
为 0；WHO 指南原先被误识别为一列表格的页面回到正文文本路径，重复字形残留为 0。回归测试覆盖
“异常整词可修复、正常英文不被破坏、伪表格被过滤、真实业务表格保留”四类边界。

本轮仍未解决扫描页 OCR、图片动作语义、复杂跨页表格、多栏阅读顺序的全部问题；这些仍受页面路由、
OCR/视觉服务、专业审核和质量门禁约束，不能因为文本层清洗通过就自动发布。

## 第三轮：解析前后对比评测（2026-08-15）

新增 `scripts/compare_document_quality.py`，用于比较同一份原始资料在两个解析管线版本下的报告：

- 比较前先校验来源路径集合；如果两份报告不是同一批资料，直接返回错误。
- 对可比较来源校验 SHA-256，避免把换文件误判为解析器改善。
- 噪声率、碎片率、重复率、重复字形残留、缺页和 OCR 页数越低越好；父节点、表格和页面覆盖率越高越好。
- 发现质量回归或状态降级时返回非零，供后续 CI/重建任务阻断使用。
- `REFERENCE_ONLY` 文档也输出解析指标，但状态仍不可发布，避免参考资料的解析质量无法评估。

使用上一版本 `0f8d181` 和当前版本 `c121b8a` 对本地 manifest 的 21 份资料进行对比，结果为：

- 演示版身体活动指南的重复字形残留从 8 个内容块降为 0；WHO 指南从 2 个内容块降为 0。
- 身体活动指南完整版的表格结构完整率从 `0.944444` 提升到 `1.0`；但伪表格回正文后，短碎片率从
  `0.124656` 上升到 `0.128298`，比较器将其标记为潜在回归，不能直接忽略。
- WHO 指南也出现短碎片率上升，且本身仍因缺页/OCR 被 `BLOCKED`；当前没有任何知识版本重建或发布动作。
- 总体发布状态未因本轮解析器变化自动放行，当前仍为 `PASS=9`、`REVIEW_REQUIRED=4`、
  `BLOCKED=5`、`REFERENCE_ONLY=3`。

这次对比的意义是：不仅证明重复字形修复有效，也暴露出“伪表格回正文后短块增加”的后续问题。该问题
已经记录为阶段 12.1 的收尾任务；在此之前不调整解析器、不重建索引，也不能因为重复字形已经归零就跳过
最终上线前的复核。

由于解析清洗和质量指标已经改变，解析管线版本已提升为 `2026.08.15.1`。历史审核报告和发布凭证
不会自动继承本轮结果，后续必须重新解析、重新生成质量报告，并按文档风险完成审核后才能发布或重建索引。

## 最终阶段第一轮：版面、父子上下文与质量口径优化（2026-08-30）

本轮正式进入约定的 PDF 深度解析阶段。目标不是把所有 PDF 强行转成“看起来完整”的文本，而是让解析器在
版式复杂、图片密集、原生文字层不可靠时能够保守降级，并且把清洗证据交给质量门禁和人工审核。

本轮完成的能力：

1. **页面版面画像**：保留检测到的列数、页眉/页脚清除数量、目录页标记和断词修复数量。普通单栏页面继续使用
   `pdfplumber` 原生文本流；只有图片占比高、坐标证据充分且存在至少三个横向文本区域时才启用坐标排序，避免把
   正常双栏指南误重排。
2. **目录与页眉页脚处理**：高置信度目录页整页排除；跨页重复且位于边缘的行、政府网站导航/版权模板、正式指南
   页脚和 HHS 演示稿来源声明不进入正文。目录页会记录在 `excluded_pages`，不会被质量报告错误计算为漏页。
3. **断词与字体映射修复**：修复 HHS PDF 的 U+0083 项目符号和整词重复字形；对英文行尾断词进行保守合并，仅对白名单
   复合词保留连字符，避免把普通英文双写字母误当成噪声。
4. **章节级父节点**：PDF 文本块按照章节标题生成 `heading_path` 和章节级 `parent_content`，子节点仍限制长度用于
   Embedding，命中后可以恢复动作名称、适用人群和安全前提。质量门禁会忽略系统注入的标题前缀，再验证正文是否能回溯
   到父节点；父上下文也纳入文档校验和，确保父节点变化会触发增量重建。
5. **表格边界保护**：正文坐标重排会排除已经识别的表格区域，表格仍保留 Markdown 表头、列数、页码和行范围；伪表格
   继续回退正文路径，避免表格内容和文字层重复召回。
6. **真实资料回归**：使用当前知识清单的 21 份资料重新解析，质量报告为 `PASS=9`、`REVIEW_REQUIRED=4`、
   `REFERENCE_ONLY=3`、`BLOCKED=5`。与深度优化前报告比较，`4` 份资料指标改善、`0` 份资料回归、`17` 份保持不变；
   正式身体活动指南的目录第 3 页已记录为有意排除，不再产生假漏页；其余缺页/OCR 阻断和图片密集资料的人工审核要求
   仍然保留。当前未自动重建 PostgreSQL 知识版本。

本轮明确保留的边界：

- 扫描页、图片中的动作/姿态、复杂信息图仍不能靠原生 PDF 解析器推断，必须等待 OCR/视觉服务或人工审核；本轮没有
  伪造 OCR 内容，也没有把参考资料直接发布为可检索知识。
- 跨页表格的语义续接、图片区域级动作标注、真实 OCR 置信度和渲染后的视觉回归仍是下一轮收尾任务。表格“Markdown
  语法完整”不等于已经完成跨页语义校验，不能把两者混为一谈。
- 真实来源中已经缺失的字词、扫描页中的文字和原文件本身的错误不能安全猜测；如果关键数字、单位、动作步骤或禁忌
  信息缺失，应继续阻断并进入审核队列。

验证结果：Ruff 通过，Agent 全量测试 `423 passed, 9 skipped`；真实 PDF 质量报告已输出到本轮离线验收结果，脚本

## 最终阶段第二轮：跨页表格续接与形状校验（2026-08-30）

本轮补齐跨页表格的保守处理：每张 PDF 表格记录规范化表头签名、第一列表头、列数、非空行数和续表组标识。
只有同时满足“页码连续、相邻页各只有一张表、完整表头一致、列数一致”时，才标记为同一续表组；内容仍按页保留、
重复表头仍保留，便于单个检索块自描述和来源定位，没有把不同页面的原文强行拼成一张不可回溯的大表。

以下情况不会自动合并：相邻页面有多张相同表头的表、第一列表头相同但列数变化、表头缺失或结构无法确认。它们会写入
`AMBIGUOUS_REVIEW` 或 `SHAPE_MISMATCH_REVIEW` 元数据，并使表格完整性门禁不通过，等待人工复核。质量报告新增续表数量、
歧义续表数量和形状不一致数量；解析前后比较也会把后两项按“越少越好”处理。

真实资料验证发现：正式身体活动指南第 51–52 页、演示版第 19–20 页分别被正确关联为续表组；当前 21 份资料仍为
`PASS=9`、`REVIEW_REQUIRED=4`、`REFERENCE_ONLY=3`、`BLOCKED=5`，所有识别到的表格 `table_integrity=1.0`，
没有产生歧义或列数不一致记录。Ruff 通过，Agent 全量测试 `429 passed, 9 skipped`；本轮没有重建知识库。

## 最终阶段第四轮：OCR 结果安全契约（2026-08-30）

本轮把 OCR 从“能发 HTTP 请求”收紧为可以进入企业审核链路的结果契约。独立 OCR 服务每个块必须返回：正整数
`source_page`、`0~1` 的 `confidence`，以及页面归一化坐标 `source_region={x,y,width,height}`。Agent 不直接保存浮点元数据，
而是将置信度和区域坐标转换为 `0~10000` 基点写入元数据，便于稳定比较、审计和后续引用定位；页码越界、区域越界、
区域尺寸为零、字段缺失或类型错误会直接拒绝响应。

OCR 与原生文字层的合并规则也已接入 PDF 解析器：

- 只有置信度不低于 `AGENT_RAG_PDF_MIN_OCR_CONFIDENCE`（默认 `0.75`）且来源区域完整的 OCR 结果，才允许解除页面的
  `OCR_REQUIRED` 阻断。
- 低置信度结果仍保留为审核证据，并标记 `ocr_low_confidence=true`，但不会让页面生成可发布知识版本。
- 同页 OCR 文本如果只是原生文字层的重复副本，会被丢弃并记录“已去重”；不同内容不会被粗暴拼成一段，避免引用位置和
  原文边界丢失。
- OCR 结果只能覆盖解析器请求的缺失页，不能通过伪造其他页码影响页面状态；`OCR_AND_VISUAL_REVIEW_REQUIRED` 在 OCR
  成功后仍保留视觉审核要求。

本轮新增 OCR 合同、置信度门禁、同页去重测试，并完成 Ruff、格式检查、Mypy 和全量测试。当前仍未接入真实 Linux/GPU OCR
服务，因此没有把模拟响应当作真实识别质量；真实服务上线后还需要使用扫描 PDF 做置信度分布、页级覆盖率、表格和动作图文
回归，质量不达标时继续阻断。
