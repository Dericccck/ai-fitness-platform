# Agent 停止功能：复核问题修复计划

日期：2026-10-07。状态：已实现并通过验收，启用需迁移至 0047。以下保留实施计划，并在第 8 节记录实际交付。

关联设计：[Agent 任务中途取消](agent-task-cancellation-design.md)。

## 1. 目标与范围

修复本次复核确认的三个问题：

| 问题 | 已确认的触发条件 | 修复后的行为 |
| --- | --- | --- |
| 取消轮次污染摘要 | 本轮摘要先保存，取消随后赢得完成状态竞争 | 本轮摘要不发布，下一轮继续使用此前已提交的摘要与完整历史 |
| 正常历史因 run 过期丢失 | 上轮 COMPLETED，但 run 结果过期或记录被清理 | 正常历史仍可续聊，结果保留期限不决定历史是否有效 |
| 临时查询失败丢失停止入口 | 取消已受理，随后 GET 出现一次网络错误或 503 | 保留原 run、部分文本及恢复入口，查询恢复后呈现真实终态 |

本次覆盖普通流式对话停止及恢复。保留原有 JSON 对话、确认单批准/恢复行为；增加兼容回归，但不扩展为可取消的业务执行。断网、刷新仍不自动发起取消。

## 2. 必须维持的规则

1. 完成与取消仍由 PG 对同一 run 的条件更新决定，前端不能自行判定 CANCELLED。
2. 可见摘要和可复用历史只包含已提交轮次；取消轮次不能通过摘要再次进入上下文。
3. “结果已过期”“网络不可达”“任务已取消”是三种不同事实。
4. 取消结果待确认期间保留同一个 run_id，不自动重新 POST 对话，不覆盖恢复记录。
5. 摘要提交、历史提交及迟到回调必须核对会话范围和版本，不能覆盖较新的轮次。

## 3. 后端批次：统一轮次完成事实，再修摘要

两个后端问题共享提交边界，建议作为同一批交付。不要仅把 `prior is None` 改成成功，也不要仅在摘要写入前增加一次状态查询；前者可能接受不完整历史，后者仍存在查询后的取消竞争。

### 3.1 保存独立于结果过期的完成凭据

建议新增 PG 会话提交元数据，每个服务端派生的授权会话范围保存一条，包含最近提交的 run_id、提交版本和时间。复用现有 owner/scope 摘要，不存身份令牌或重复的消息正文。

- 正常完成时，将 `RUNNING → COMPLETED` 和会话提交元数据更新放在同一数据库事务内；取消先赢时两者都不能提交。
- run 的结果接口继续遵守原有 `expires_at`，但 Supervisor 判断历史是否有效时使用独立的完成凭据，不依赖结果查询接口。
- 在现有会话锁与 fencing 保护下读取 checkpoint：上一轮 run_id 匹配完成凭据则使用完整历史；明确未提交时使用 `turn_base_messages`。
- 凭据生命周期跟随会话/checkpoint 的保留与授权清理，不随 24 小时的响应结果清理一起删除。新增清理和权限撤销联动，避免永久保留无引用元数据。
- 不在 checkpoint 中提前设置“已提交”，也不依赖完成事务后一次可能失败的 checkpoint 写入来证明成功。

迁移与兼容：新增 Alembic revision，保留已有 0046 的职责与内容。对尚存、范围明确的 COMPLETED 记录回填凭据；原有不带 managed run_id 的 JSON/旧 checkpoint 保持兼容路径。已经物理删除且没有其他完成凭据的旧记录无法可靠补证，使用最后可信快照并记录脱敏诊断，不把未知轮次猜成成功。

### 3.2 摘要采用“生成候选 → 随完成提交发布”

- 拆分 `SessionSummaryService` 的摘要生成和正式保存。模型调用、清洗及加密在短事务外完成。
- 本轮生成的摘要先作为内部候选保存，携带来源 run_id、会话范围和基准版本；尚未提交时不能替换正式摘要。
- 管理器提交 COMPLETED 时，在同一 PG 事务内发布候选摘要并更新会话完成凭据。条件更新失败则丢弃候选，保留上一版正式摘要。
- 摘要生成失败仍允许回答正常完成并保留旧摘要；数据库提交失败不能向客户端宣称 COMPLETED。
- 摘要不需要生成时，只提交轮次完成凭据，继续使用原正式摘要。
- 将压缩 checkpoint 的动作放到下一轮持锁加载正式摘要时完成，避免本轮取消前写入候选摘要，也避免完成后的迟到压缩覆盖新一轮 checkpoint。
- 正式摘要增加来源/版本元数据。处理升级前没有来源信息的摘要：能证明来源有效则沿用，无法证明时跳过或基于可信历史重建；不得通过新逻辑无条件继续加载可能已污染的摘要。
- 检查所有 `maybe_summarize()` 调用方，确保 JSON 对话和确认执行恢复不会被错误套入流式取消事务，也不会绕过版本检查覆盖更新的摘要。

实现时优先使用有类型的内部完成数据传递候选摘要，禁止把摘要正文、事务对象或 RunControl 塞进对外 ChatResponse 或 checkpoint。

## 4. 前端批次：保留结果待确认的操作

### 4.1 明确操作状态

将“是否正在等待一个 HTTP 请求”与“是否还有未确认的任务”分开。建议抽取可测试的会话操作状态管理，供发送、停止和刷新恢复共用：

| 状态 | 展示及允许操作 |
| --- | --- |
| 生成中 | 展示增量，可停止 |
| 正在停止 | 保留已展示内容，查询原 run，阻止重复提交 |
| 结果待确认 | 保留原 run 与部分内容，允许“重试查询”；取消意图未确认时允许重试停止 |
| 已取得终态 | 按 COMPLETED / CANCELLED / FAILED / UNKNOWN 展示真实结果，释放当前活动槽位 |

`FAILED`、`UNKNOWN` 虽是数据库终态，也不能显示“已停止”。保留可供用户核对的结果说明/任务关联信息；业务副作用继续按既有查询与确认协议核对。

### 4.2 有界重试和错误分类

- 对 GET 的网络错误、单次请求超时、408、429、502、503、504 做有界重试；429/503 如有 `Retry-After` 则遵守，并受总体等待预算限制。
- 初始建议退避 1、2、4、8 秒，单次上限 8 秒并加入抖动；沿用约 5 分钟总体预算。使用可注入时钟/等待函数测试，避免测试实际等待数分钟。
- 总体预算耗尽后进入“结果待确认”，停止自动轮询但保留手动恢复入口。手动恢复创建新查询 controller，继续查询原 run。
- 401/403 转为重新认证/权限提示；不无限重试，不向另一登录主体展示旧任务内容。账号切换继续遵守现有范围清理。
- 已登记任务的 404 不能显示已取消：提示不存在或已过期，不自动循环。只有“首次 POST 尚在登记”的短窗口继续使用已有 404 取消重试规则。
- 生命周期 AbortSignal 表示卸载或范围切换，应立即结束；单次请求超时属于可恢复错误，不能与生命周期中止混用。

### 4.3 恢复记录与清理时机

- 移除 `finally` 无条件释放业务操作的逻辑；只在获得规范终态或明确完成身份/会话切换时释放当前任务。
- 查询失败保留原 `runId`、`cancelRequestId`、会话范围、取消意图及必要恢复状态；刷新后恢复同一操作，不生成新的取消请求 ID 代替重试。
- 在存在未确认任务时禁用新提交，并在提交入口再次检查，防止直接调用或快速点击覆盖 `fitness.pending-chat`。
- 取消请求本身超时也进入核对路径。查询发现取消已受理则继续等待；发现仍 RUNNING 时允许复用原取消请求 ID 重试。
- COMPLETED 赢得竞争时显示完整回答；CANCELLED 才标记已停止。短暂查询故障不得把已经展示的部分文字替换为通用失败文案。
- 保留旧回调作用域校验，避免上轮停止/查询响应覆盖当前轮次。
- 对恢复记录增加版本与读取兼容，不持久化凭证；不为此次修复新增聊天正文的浏览器持久化。

预计修改 `fitness-web/src/chatRun.ts`、`api.ts`、`App.tsx`、`types.ts`，必要时增加独立操作控制模块。现有“停止”按钮位置不变，仅补充待确认状态的恢复操作。

## 5. 实施顺序与交付点

1. **先补失败用例**：将复核中的三个复现整理为回归测试，确认修复前失败；增加摘要与完成事务的关键竞争测试。
2. **落地后端提交边界**：新增元数据与迁移，完成历史判断改造，再接入候选摘要的原子发布。两个问题一起验收。
3. **落地前端恢复状态**：先实现错误分类和有界重试，再接入 App 与刷新恢复，最后补交互提示。
4. **完成综合验收**：单元回归、真实 PG/Redis 隔离验收、浏览器故障注入验证；更新原设计和服务 README 的已实现范围。

建议分成三个可审阅提交：后端及迁移、前端恢复、验收与说明。每批测试随对应实现提交。

## 6. 必须新增的验收用例

| 编号 | 场景 | 必须成立的断言 |
| --- | --- | --- |
| B1 | 候选摘要生成后，取消先赢 | CANCELLED；旧摘要未覆盖；下轮模型输入无取消轮次内容 |
| B2 | 完成先赢，随后取消 | COMPLETED；凭据与摘要一起提交；取消不能撤销完整回答 |
| B3 | 回答已完成，结果过期/被清理后续聊 | 完整上一轮历史仍在，结果 GET 仍遵守过期策略 |
| B4 | 已取消或 UNKNOWN 的 run 被清理 | 不把其 checkpoint 当完整历史；使用此前可信快照 |
| B5 | 完成事务失败、进程在提交边界中断 | 无部分发布；摘要、完成凭据与 run 终态相互一致 |
| B6 | 摘要生成失败或阈值未达到 | 正常回答可完成；原正式摘要保留 |
| B7 | 旧轮迟到提交/压缩，新轮已开始 | 不覆盖新轮摘要和 checkpoint；范围/版本检查生效 |
| B8 | 迁移回填、旧 checkpoint、JSON、确认执行恢复 | 有明确兼容路径，既有对话与确认流程回归通过 |
| F1 | 取消受理后一次 503/断网，随后 CANCELLED | 自动恢复；只取消原 run；部分文字保留并正确标记停止 |
| F2 | 连续查询失败耗尽预算 | 进入待确认；原记录不变；不能发送覆盖；可手动恢复 |

| F6 | 快速发送后停止、反复点击、旧请求迟到 | 使用稳定操作 ID；不覆盖恢复记录；不重复执行模型 |

后端使用真实 LangGraph 验证下轮输入，使用真实 PostgreSQL 验证事务原子性和迁移；仅内存仓储不足以证明竞争正确。前端除轮询函数测试外，必须覆盖操作状态与恢复记录的联动。

综合验收沿用 `make runtime-delivery-check`、`make runtime-delivery-live-check`，并补跑 Supervisor、session summary、取消、迁移相关测试；通过前端测试、TypeScript/生产构建、相关 Ruff/mypy 检查。浏览器验证生成 → 停止 → 临时断网 → 恢复 → 下一轮，同时检查请求中没有第二次 POST 对话。

本次复核基线为后端 119 项、前端 14 项及前端构建通过；这不是新增修复验收结果。完成标准以以上场景覆盖为准，不以测试数量为准。

## 7. 启用与完成标准

- 在隔离数据库验证新迁移升级、兼容读取与回滚限制；正式启用前执行迁移，并 drain 旧 worker，避免旧版本继续绕过摘要提交边界。
- 新凭据纳入 readiness 和既有隐私/生命周期清理；不为修复而延长完整回答正文的保留期。
- 三个原始复现全部转为通过，新增验收用例通过，既有取消/确认/流式恢复回归无退化。
- 文档明确记录旧记录无法补证的处理方式，以及结果待确认时的用户操作。
- 验收前保持本计划为“待实施/实施中”，完成后附实际测试结果与剩余限制。


## 8. 实际交付与验收记录（2026-10-07）

- 新增 `20261007_0047` 与 `agent_chat_history_commits`：每授权会话一条完成凭据，和 run COMPLETED 同事务提交；旧记录在可信 checkpoint 引用下懒回填。响应到期/删除不会删除仍有 checkpoint 引用的凭据。
- 摘要只生成内部候选，完成事务按基准版本发布；取消、事务回滚和版本冲突不会覆盖正式摘要。下一轮持会话锁加载正式摘要并压缩消息；确认执行恢复的摘要处理也在会话锁内，去除完成后的迟到 checkpoint 改写。
- 凭据纳入主体派生上下文撤销，以及有界 checkpoint 引用检查。支持 checkpoint 使用单独数据库；读取故障时保留凭据，不按时间猜测删除。
- GET 临时故障退避重试，遵守 Retry-After 与整体预算。预算耗尽或无法确认时保留原操作和部分文字，提供“重试查询”；新提交不能覆盖原记录。恢复记录 v2 保留原取消请求 ID 与意图，兼容旧记录。
- 身份范围变化事件取消本机恢复等待并清理旧界面；普通查询故障不释放任务。COMPLETED/CANCELLED/FAILED/UNKNOWN 依数据库事实分别处理。
- 自动回归：后端相关与运行时综合测试 172 项通过；前端 19 项通过，TypeScript/生产构建通过；相关 Ruff/mypy 通过。
- 隔离 PG/Redis：真实完成/取消竞争、候选发布、事务回滚、迟到版本冲突、结果过期、旧记录回填、无引用凭据清理、主体撤销、确认单边界和浏览器认证契约通过；迁移 `head → 0044 → head → base` 通过并清理临时库。
- 浏览器（真实取消 API/PG，固定测试模型）：503 后自动恢复、待确认时保留文本和禁用新提交、手动重试原任务、刷新恢复、停止后续聊通过。请求计数确认查询/刷新没有产生重复 POST 对话，页面控制台无未处理错误。

启用步骤：先 drain 旧执行者，在仓库根目录执行 `make agent-migrate`，再启动后端及新前端。0047 清除未绑定来源的旧派生摘要，后续根据可信历史重新生成；不会删除 checkpoint 或业务数据。

限制：迁移前已物理删除且无完成凭据的 run 无法补证，使用最后可信快照；刷新不持久化此前的增量正文。404/权限失败不会被当成取消成功，保留待确认提示供重试或重新认证。
